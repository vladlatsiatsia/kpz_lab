# Дотримання принципів програмування у проєктуванні додатку (Лабораторна 1)

У цій роботі реалізовано об'єктно-орієнтовану структуру для керування HTTP-відповідями (клас `Response`), яка чітко демонструє базові принципи розробки.

## 1. Принцип KISS (Keep It Simple, Stupid)
Клас `Response` вирішує конкретну задачу — збір заголовків, встановлення статус-коду та вивід контенту — найпростішим і зрозумілим шляхом за допомогою вбудованих можливостей PHP (`http_response_code`, `header`). Код не перевантажений зайвими абстракціями, фабриками чи сторонніми залежностями. Все логічно, компактно й виконує лише свою роботу.
* **Доказ у коді:** Проста реалізація методів `setStatus()`, `addHeader()` та виведення через `echo` в методі `send()`.

## 2. Принцип YAGNI (You Aren't Gonna Need It)
У класі немає жодного методу "на майбутнє" (наприклад, для складного парсингу JSON, роботи з куками чи сесіями), які не потрібні для поточної задачі відправки простої відповіді. Створено лише мінімально необхідний набір властивостей (`$statusCode`, `$headers`) та методів для поточної роботи програми.
* **Доказ у коді:** Наявність лише трьох базових методів для керування відповіддю без надлишкового функціоналу.

## 3. Принцип Fluent Interface (Плинний інтерфейс)
Для зручності розробника методи `setStatus()` та `addHeader()` повертають `$this` (поточний об'єкт). Це дозволяє викликати методи "ланцюжком", що робить кінцевий код використання об'єкта більш читабельним та елегантним.
* **Доказ у коді:** Рядки `return $this;` у методах зміни стану об'єкта, що дозволяє писати компактний клієнтський код.
